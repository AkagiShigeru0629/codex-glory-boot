# Codex 荣耀启动器

这是面向 Windows 10/11 x64 和 Microsoft Store 版 Codex 的独立 Python 启动器。
当前实现范围包括并行启动 Codex、等待主窗口框架稳定、按 Codex 整窗可见外框连续播放荣耀主题动画，以及桌面窗口管理器（DWM）交接。

第二阶段 A 的窗口适配已经实现，并完成当前单显示器环境下的实机启动验证；多显示器、负坐标和不同 DPI 仍需单独验收。第二阶段 B 的应用内壁纸已在 Codex `26.1103.4239.0` 上完成实际注入和视觉验收，并针对当前 `26.1111.2228.0` 更新了能力配置；完整 Codex 用户界面皮肤不在当前范围内。

## 环境

- CPython 3.14
- PySide6 6.12
- Windows 10/11 x64

所有依赖安装在项目内 `.venv`，不修改系统 Python。

## 开发命令

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

生成发布目录与压缩包：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\package.ps1
```

## 专用入口

构建完成后可创建桌面专用入口：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install.ps1
```

恢复脚本根据安装时记录的 SHA-256 删除专用入口；如果快捷方式在安装后被修改，会拒绝自动删除：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore.ps1
```

替换已有官方入口必须使用 `-ReplaceOfficial`，并通过 `-ShortcutPath` 明确指定目标。恢复时会重建原快捷方式的路径、参数、图标和工作目录。

## 当前验证结果

以下只记录最近一次明确验证的结果。发布包测量值、文件体积和 SHA-256 只对当次构建有效，不作为后续构建的固定状态；完整历史证据见更新计划。

- 2026-11-12 自动测试：296 通过、0 失败。
- 2026-11-16 连续播放修订：302 通过、0 失败；启动器在 Codex 壳窗口连续稳定后开始动画，正文、皮肤或内容后续加载不再暂停或延长开屏时间线。
- 当前演示媒体：1920×1080、60 帧、7.700 秒 H.264；5.2 秒后进入“荣耀丨codex”结尾，6.4–7.1 秒执行 CRT（阴极射线管）收束，7.1–7.6 秒由 DWM 淡入 Codex。
- 2026-11-12 首个窗口对齐与壁纸交接门控修复打包基准：首个可见窗口 `298.7 ms`、媒体首帧 `509.8 ms`、Codex 启动请求 `301.4 ms`。
- 2026-11-16 最终回归包基准：首个可见窗口 `262.4 ms`、媒体首帧 `472.8 ms`、Codex 启动请求 `270.3 ms`。
- 当前压缩包 SHA-256 为 `3b33517508785edb7d12c7b293e6bf99681a18690029479a5120fa57d9458dd3`。
- 为避免可见基准窗口干扰人工录屏，本次窗口稳定修复后的打包未重新运行 `-Benchmark`；上一组基准只代表旧几何策略，不作为本次最终性能数据。
- 当前媒体时长、时间点和关键帧以 `config/launcher.example.json` 和设计说明为准，启动逻辑不写死 8 秒。
- 后续重新打包时必须重新测量性能与 SHA-256，不得沿用本次构建数据。

打包基准使用无外部启动副作用的后端，为避免读取真实 Codex，它会直接显示并启动媒体。因此上述指标只验证打包运行时开销，不代表正常冷启动的“等待窗口后开播”时点，也不覆盖真实 Codex 窗口发现与几何校准。真实 Store 版 Codex 冷启动、普通窗口、最大化窗口、多显示器、负坐标和不同 DPI 仍需在完全退出 Codex 后人工验收。

## 可选应用内壁纸

- 当前配置已启用；`--disable-skin` 可在单次启动中强制关闭皮肤。
- 只有同时存在已登记的兼容配置、壁纸文件和 Store 应用启动条件时，才使用 `127.0.0.1` 随机端口；激活后继续用本次进程的真实包版本和能力探测做最终放行。
- 启动器会从当前用户的应用包注册信息自动选择最新 Store 版 Codex 并刷新运行时记录；安装脚本或 `scripts/sync-codex-runtime.ps1` 仍可作为正在运行应用时的补充入口。
- `skin_profiles.json` 当前为 Codex `26.1111.2228.0` 登记精确配置，并登记显式 `26.*` 能力系列；`27.*` 等未登记主版本仍会跳过。页面必须同时具备根节点、输入区和主题令牌，写入后还要通过样式标记与背景检测。
- 如果调试激活接口启动失败，启动器会立即改用不带调试参数的原生 Shell 路径启动 Codex，壁纸增强失败不会阻断 Codex。
- 页面内按 `Ctrl+Alt+Shift+R` 恢复原生外观；启动器存活期间检测到页面重载会自动重新注入。连续快速重连最多尝试三次，成功健康检查后恢复预算。

## 架构摘要

- `domain/` 使用不可变数据类和纯函数，决定交接进度、几何和目标矩形，可完全离屏测试。
- `services/` 用线程安全状态发送 Codex 启动请求；明确失败时等待 1 秒重试，请求看似成功但 8 秒内没有主窗口时再次激活，最多三次。主窗口出现后停止重复激活；250 ms `QTimer` 触发后台窗口探测，短暂漏检不会重置稳定窗口。获得激活进程号后只接受该进程的窗口；壁纸连接在主页面替换启动壳时重新发现目标；DWM 完成淡入后直接关闭启动器，避免叠加第二次淡出。
- `adapters/` 集中封装 Win32、DWM 和快捷方式事务。窗口按进程名、包路径、窗口类、可见性、客户区和响应性筛选，并用 DWM 扩展外框取得实际可见的整窗矩形。
- `ui/` 冷启动时保持启动器隐藏，直到本次激活的 Codex 主窗口连续稳定并取得有效整窗矩形；几何读取失败时继续等待稳定回调，不再回退显示历史最大化矩形。窗口框架就绪后动画连续播放到结束，壁纸和页面内容可在后台继续加载。
- Codex 已运行时，专用入口在显示动画前聚焦现有窗口并退出，避免先播放动画再跳转或重复启动。
- 视频与海报采用覆盖式缩放，填满 Codex 整窗外框；非 16:9 窗口会裁切画面边缘而不保留黑边。
- 媒体末尾把最终画面压成横向亮线并收缩为中央亮点；亮点熄灭后 DWM 在整窗矩形内将真实 Codex 从透明淡入。
- DWM 缩略图在过渡区间持续更新并覆盖整窗内容；注册或更新失败时改为窗口淡出。所有交接原因由同一策略决定退出、报错或激活窗口。
- Codex 窗口框架连续稳定后动画不再受页面内容、日志标记或壁纸就绪状态阻塞；CRT 收束结束后保留 0.2 秒稳定画面，随后交接给真实窗口。
- 动画窗口先结束时，启动器窗口立即关闭，但后台进程继续等待已启动的壁纸注入完成或失败；用户按 `Esc` 跳过时则同时取消皮肤任务。
- 播放位置到达 `duration - 50 ms` 时主动暂停在视频自身的最后一帧，不进入 `EndOfMedia`，也不增加额外图片或覆盖层。
- 最终交接先聚焦 Codex，再让启动器在 360 ms 内平滑淡出；`Esc` 跳过也走同一淡出流程。
- PyInstaller 使用 `onedir`。Windows 系统 ICU 负责提供 Qt 所需的 `ucnv_open`，发布规格会排除不兼容的同名私有 ICU。

架构讲解时可强调三个关键取舍：先用有限等待换取无小窗跳变和无边框外露、领域状态机与平台 API 解耦、DWM 失败仍保证回到可操作的 Codex。

Microsoft Store 包的稳定入口是 `OpenAI.Codex_2p2nqsd0c76g0!App`。新版桌面主程序名为 `ChatGPT.exe`，旧版本可能使用 `Codex.exe`，配置同时兼容两者，并通过 `OpenAI.Codex_` 包路径前缀排除同名程序。

## 目录

- `src/glory_boot/domain/`：不依赖 Qt、文件系统和 Windows API 的纯领域逻辑。
- `src/glory_boot/services/`：媒体、启动、会话和日志编排。
- `src/glory_boot/adapters/`：Qt、Win32、DWM、快捷方式等外部边界。
- `src/glory_boot/ui/`：窗口显示和用户输入。
- `scripts/`：环境、测试、构建、安装、恢复和媒体工具入口。
- `tools/append_crt_shutdown.py`：从现有成片生成确定性 CRT 收束和 DWM 交接黑场。
- `tests/`：自动化测试。

## 恢复

启动器不会修改 Codex 安装目录。专用入口和可选官方入口替换均可通过安装记录恢复。
