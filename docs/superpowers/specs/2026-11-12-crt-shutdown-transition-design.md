# Codex 荣耀启动器 CRT 收束转场设计

**状态：** 已批准、完成自动验证并由秋月大人确认保留

## 意图

当前启动动画在 Codex 主窗口内完整播放后直接淡出，画面与真实窗口之间缺少明确的视觉收束。本次在动画末尾追加约 `0.7` 秒的 CRT（阴极射线管）电视机关闭效果：最终画面先垂直压成横向亮线，再横向收缩为中央亮点，亮点熄灭时真实 Codex 从黑色背景中淡入。

当前版本媒体时长改为约 `7.7` 秒，但业务逻辑、配置校验和测试不得重新写死为 8 秒或 7.7 秒。后续媒体仍可通过更新 `Duration`、关键时间点和媒体规格共同变更。

## 目标

- 在 Codex 主窗口内形成明确的“电视机关闭”视觉收束。
- 使用预渲染视频完成垂直压缩与水平收缩，避免实时缩放控件造成裁切感和 DPI 差异。
- Codex 窗口框架连续稳定后，收束随视频时间线连续播放；页面内容可在背景继续加载。
- 亮点熄灭后由 DWM 以全窗口目标矩形淡入真实 Codex。
- DWM 不可用时继续使用启动器窗口淡出，回到可操作的 Codex。
- 媒体时长、收束起点和交接时间仍由配置驱动。

## 非目标

- 不做反向“电视开机”展开动画。
- 不增加音效、闪烁循环或 CRT 扫描线常驻效果。
- 不复制参考项目的源码、素材或逐帧实现。
- 不改变 Codex 安装目录、页面结构或聊天数据。
- 不允许 CRT 效果成为启动成功的前提。

## 已考虑方案

### 方案 A：把 CRT 收束追加到视频

在现有正式媒体末尾生成确定性帧序列，由 QtMultimedia 按正常视频播放。垂直压缩、亮线和亮点保持一致，跨 DPI、多显示器和负坐标行为最稳定。**秋月大人已选择。**

### 方案 B：实时缩放 Qt 窗口

不需要重编码视频，但视频控件通常表现为裁切而不是垂直压缩，且顶层窗口几何动画需要额外处理物理像素与 DPI。**不采用。**

### 方案 C：DWM 缩略图实时压缩

能显示真实 Codex 内容，但 DWM 只支持目标矩形和透明度，无法自然实现画面垂直压缩。**不采用。**

## 视觉与时间线

当前媒体版本采用 `1920×1080`、`60` 帧。CRT 收束从 `6.4` 秒开始，持续 `0.7` 秒：

| 相对时间 | 内容 |
| --- | --- |
| `0–0.28` 秒 | 最终画面按平滑曲线垂直压成约 4–6 像素高的亮带，边缘出现短暂冷白辉光 |
| `0.28–0.34` 秒 | 亮带保持为水平扫描线，亮度轻微回落 |
| `0.34–0.62` 秒 | 扫描线从两端向中心收缩为约 8×8 像素的亮点 |
| `0.62–0.70` 秒 | 亮点快速熄灭，画面进入纯黑 |

当前版本时间点：

- `Duration = 7.7`
- `HoldAt = 6.4`
- `TransitionStart = 7.1`
- `TransitionEnd = 7.6`
- CRT 收束区间为 `6.4–7.1`，之后媒体保持黑色。
- `7.1–7.6` 由 DWM 以整窗目标矩形将真实 Codex 从透明淡入到不透明。
- 视频结束后最多再保留 `0.2` 秒最终稳定画面，随后聚焦真实 Codex 并关闭启动器。

各时间点仍必须满足：

`0 <= HoldAt < TransitionStart < TransitionEnd < Duration`

## Codex 内容仍在加载

- 动画不读取页面内容、日志挂载标记或壁纸加载状态。
- 媒体到达 CRT 区间后连续播放，不暂停、不循环、不等待。
- 视频结束后由 DWM 展示当前 Codex 窗口；若页面仍在加载，加载耗时由 Codex 自身承担。

## 媒体生成

- 新增独立工具，从当前正式视频截取 `0–6.4` 秒内容，在末帧之后生成 `42` 帧 CRT 收束，并补足黑色交接帧。
- 新工具不得依赖 `assets/local/` 中的非公开素材。
- 输出继续为 `1920×1080`、`60` 帧、H.264、`yuv420p` 和 fast start。
- 生成结果替换 `media/startup.mp4`；海报继续匹配动画开始时使用的有效画面，不替换为 CRT 末帧。
- 所有帧生成必须是确定性的，相同输入产生相同帧数和时间结构。

## 交接

- `screen_frames` 在 `7.1` 和 `7.6` 秒均使用完整视口矩形，不再通过空间扩张模拟窗口出现。
- `7.1` 秒缩略图透明度为 `0`，`7.6` 秒为 `1`。
- DWM 更新失败时，启动器窗口自身在 `7.1–7.6` 秒从 `1` 淡出到 `0`。
- 交接完成后先聚焦真实 Codex，再关闭启动器。
- 最终停留时间从当前 `2.5` 秒调整为 `0.2` 秒；Codex 尚未就绪时仍由既有等待和超时状态机控制，不受该值影响。

## 测试

- 渲染器总帧数、输出时长、CRT 帧数可由配置常量计算，不写死 8 秒。
- CRT 帧中最终画面的高度单调下降，扫描线最终宽度单调下降。
- 收束结束帧接近纯黑，不能停留在完整“荣耀丨codex”画面。
- 新视频保持 `1920×1080`、`60` 帧、H.264，时长与配置一致。
- 配置时间点满足顺序约束，所有 `screen_frames` 位于媒体时长内。
- Codex 页面内容晚加载时，CRT 和 DWM 仍按媒体时间点完成。
- DWM 失败时仍通过窗口淡出回到 Codex。
- 最终稳定停留使用新值，媒体失败和 `Esc` 回退不变。

## 验收

- 自动测试和媒体烟雾检查全部通过。
- 无副作用打包基准记录首帧、媒体请求和启动请求；真实冷启动由秋月大人确认。
- 真实冷启动中，Codex 未就绪时能看到“荣耀丨codex”等待画面；就绪后亮线收成亮点，亮点熄灭后 Codex 平滑出现。
- 普通窗口、最大化和多显示器下收束始终位于目标窗口内，不露出桌面边框。
