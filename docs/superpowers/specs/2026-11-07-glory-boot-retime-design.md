# 荣耀开屏最终重剪设计

**状态：** 待批准

## 意图

在不改变现有荣耀主视觉体系的前提下，重新分配 8 秒开屏成片的时间结构，解决前段过长、结尾过短、硬切明显、最终画面主次不清和等待提示位置不当的问题。本次只做一次有边界的最终重剪，不以继续增加光效为目标。

## 目标

- 主画面与“荣耀丨codex”结尾的画面比例约为 `5.2 秒 : 2.8 秒`。
- 结尾拥有明确的进入、读清、稳定停留和交接节奏，不再是一闪而过。
- 保留最终画面的“确定”“返回”伪交互按钮，作为荣耀登录界面的视觉语言；它们不承担任何功能。
- 用短暂桥接替换当前硬切，降低亮度从主画面到结尾界面的突变。
- 最终画面尽量保持原素材内容和现有标题样式，只通过更长展示时间提升可读性。
- 启动器等待提示不再与画面底部信息冲突，使用画面右上安全区。
- 启动时序、配置关键帧、媒体测试和海报在同一个任务内同步。

## 非目标

- 不增加人物、新素材或第二套美术方向。
- 不移除最终画面的“确定”“返回”伪交互按钮。
- 不替换或删除“荣耀十区”及底部现有 HUD 信息。
- 不增加音轨、在线素材下载或远程更新。
- 不改变启动器的领域状态机结构。
- 不进入壁纸或 Codex 内部界面皮肤阶段。

## 当前问题证据

- 当前结尾从约 `7.17` 秒开始，仅持续约 `0.83` 秒。
- 切换前后全画面平均亮度约从 `57` 降到 `7`，属于明显硬切。
- 桌面窗口管理器（DWM）在 `6.8` 秒已开始交接，但最终标题约 `7.17` 秒才出现。
- 启动器等待文字位于底部中央，视频已有底部状态文字，最终画面底部也有登录界面信息，存在重复和遮挡风险。

## 方案比较

### 仅修改时间点

直接把切点从 `7.17` 秒移到约 `5.2` 秒，只改配置和拼接位置。改动小，但结尾仍会硬切，最终画面信息层级和等待提示冲突也没有解决。不采用。

### 完整重剪

保留 `glory1.mp4` 与 `glory.mp4` 的现有视觉，压缩前段七个效果阶段的持续时间，延长结尾的标题展示，并加入短暂亮度桥接；同时调整 DWM 交接时间和等待提示位置。该方法能一次解决已确认的问题，且不需要重新设计美术。采用。

## 时间结构

总时长保持 `8.0` 秒、`60` 帧。

| 时间 | 内容 |
| --- | --- |
| 0.0–0.8 秒 | 固定尺度、柔和起亮，保持海报与视频首帧一致 |
| 0.8–4.9 秒 | 压缩粒子、圆环、扫描、故障、爆发、纵向扫描和蓄力阶段 |
| 4.9–5.2 秒 | 短暂亮度桥接，过渡到荣耀登录界面 |
| 5.2–6.4 秒 | 荣耀登录界面进入，“荣耀丨codex”完成出现和读清 |
| 6.4 秒 | 内容门控点；未就绪时动画继续，但不启动 DWM |
| 6.7–7.6 秒 | DWM 窗口区域扩张与真实 Codex 交接 |
| 7.6–8.0 秒 | 保持最终画面，随后启动器退出 |

结尾源素材取 `glory.mp4` 约 `0.48–1.56` 秒，并在标题完成后使用末帧稳定停留。保留“确定”“返回”按钮，仅调整标题亮度、描边和轻微扫描，不改变现有控件布局。

## 视觉规则

- “荣耀丨codex”沿用现有样式，不扩大、不改字效。
- “确定”和“返回”保持原位置与样式，作为登录界面的装饰性控件，不响应鼠标或键盘。
- “荣耀十区”和其他底部 HUD 信息保持原样。
- 前段镜头只允许一次不超过 `2.5%` 的缓慢靠近，之后固定构图，不再重复推拉或漂移。
- 桥接使用短促红色扫描和亮度过渡，不使用长时间白闪或黑场。
- 等待提示定位到右上安全区，避免覆盖标题、按钮和底部 HUD。

## 配置变化

- `HoldAt`：`6.4` 秒。
- `HoldAt` 只阻止未就绪时的 DWM 交接，不暂停正在播放的动画。
- `TransitionStart`：`6.7` 秒。
- `TransitionEnd`：`7.6` 秒。
- 中间屏幕关键帧时间同步改为 `6.7` 秒，最终关键帧保持在 `7.6` 秒。
- 启动逻辑继续只读取配置，不写死 `5.2` 或 `8.0`。

## 测试与验收

- 渲染器测试确认结尾至少占成片约三分之一，且前段效果阶段仍完整存在。
- 桥接测试确认切点附近不存在超过阈值亮度的单帧跳变。
- 标题测试确认文字位于安全区，伪按钮区域保持保留。
- 会话测试覆盖 `6.4` 秒不暂停、`6.7` 秒开始交接、`7.6` 秒完成过渡，以及媒体结束后在最终帧等待。
- UI 测试确认等待提示使用右上安全区，不改变视频控件尺寸。
- 媒体烟雾测试确认 `1920×1080`、`60` 帧、`8.000` 秒、首帧海报一致且 Qt 可解码。
- 全量测试通过后重新生成发布包，真实冷启动验收仍需单独进行。

## 已确认决策

- 采用完整重剪方案。
- 保留“确定”“返回”伪交互按钮，并明确其为视觉装饰。
- 后半段素材仅做时间重采样，不删除或替换现有界面元素。
- 本次完成后冻结开屏视觉，不再无限追加效果。
