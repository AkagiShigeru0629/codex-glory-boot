# Codex 荣耀启动器第二阶段设计

**状态：** 已批准；第二阶段 A 已完成当前单显示器实机验证；第二阶段 B 已在 Codex `26.1103.4239.0` 和 `26.1106.6628.0` 完成页面能力检查；2026-11-12 起冷启动等待主窗口连续稳定后透明对齐显示；2026-11-16 起窗口框架稳定后动画连续播放，页面内容与壁纸加载不再阻塞开屏时间线

## 意图

第一阶段已经完成独立启动器、荣耀开屏动画、并行启动 Codex 和桌面窗口管理器（Desktop Window Manager，DWM）交接。第二阶段继续增强视觉连续性。2026-11-12 根据实际视觉反馈，冷启动不再追求“点击后立即显示”，而是等待 Codex 主窗口稳定后，直接在目标整窗外框内开始动画。

第二阶段分成两个互不依赖的子项：

- **第二阶段 A：启动器窗口适配。** 让独立启动器按照 Codex 主窗口的整窗可见外框显示动画，避免客户区之外仍露出原生边框。
- **第二阶段 B：Codex 内部壁纸。** 在不修改 Codex 安装目录的前提下，把本地壁纸放到 Codex 原生界面下方，并确保菜单、弹窗和输入区域仍然清晰可用。首版只处理壁纸与必要的背景透明度，不重做完整用户界面皮肤。

两个子项共享视觉目标，但采用不同技术路线。窗口适配不得依赖调试端口，内部壁纸的失败也不得影响正常启动 Codex。

## 目标

- Codex 主窗口稳定前不显示小尺寸动画；达到配置等待上限时仍显示明确失败状态并退出，避免永久空白。
- 第二阶段 A 在已知 Codex 目标窗口后，让动画、等待画面和最终交接使用同一套整窗几何。
- 第二阶段 A 支持多显示器、负坐标、125%／150% 等常见 DPI 和最大化窗口。
- 第二阶段 B 将壁纸放在 Codex 原生内容下方，不改变点击、输入、聊天和弹窗操作。
- 第二阶段 B 可以检测兼容性、主动关闭并在运行中或重启后恢复官方外观。
- 第二阶段 B 首版只验证壁纸效果和日常可用性，为是否继续开发完整皮肤提供实际依据。
- 所有产品编排、窗口适配和恢复逻辑继续使用 Python。
- 不修改 Microsoft Store 版 Codex 的安装文件或用户数据。

## 非目标

- 不把启动动画注入 Codex 页面；第一阶段动画仍由独立启动器播放。
- 不在第二阶段 A 中持续跟随 Codex 窗口拖动或缩放。
- 不在第二阶段 B 中读取、记录或修改聊天内容、账号信息、输入内容和页面文字。
- 不提供远程配置、在线主题下载、云同步或常驻服务。
- 不替换 Codex 的官方协议入口、搜索入口或安装包。
- 不承诺对未经验证的未来 Codex 版本自动兼容。
- 不增加开机自启、后台监控或自动升级能力。
- 不在本阶段实现壁纸编辑器和完整的桌面美化系统。
- 第二阶段 B 首版不重新设计按钮、字体、图标、布局和交互控件。
- 没有实际使用反馈或明确建议时，不扩展完整 Codex 用户界面皮肤。

## 反目标

- 在 Codex 主窗口稳定前先显示一个会随后跳大的小窗口。
- 让窗口适配失败阻断 Codex 启动或 DWM 回退。
- 把全屏状态、主显示器坐标或 100% DPI 写死到新逻辑。
- 将调试端口开放到非回环地址。
- 通过修改 Codex 安装目录实现外观。
- 使用覆盖在 Codex 上方的透明窗口冒充底层壁纸。
- 通过读取页面文字判断壁纸是否生效。
- 让窗口适配和内部壁纸互相成为启动前提。
- 把已知不兼容的版本静默注入后继续运行。

## 约束

- 第一阶段设计中的自适应时间线、媒体播放、停留和交接状态保持不变；仅将冷启动的窗口显示时机改为 Codex 主窗口稳定之后。
- 产品业务逻辑、测试和 Windows 适配使用 Python。
- 用户界面与媒体继续使用 PySide6 6.12 和 QtMultimedia。
- Windows 原生能力通过 Python `ctypes` 封装，包括窗口客户区、DPI、显示器、DWM 和调试端点所有权检查。
- 注入页面中的脚本只承担固定的视觉呈现与撤销，不读取页面内容，不构成独立业务逻辑。
- 不引入 Node.js 或 C# 产品代码。
- 优先使用 PySide6 已有的 Qt WebSocket 能力；只有确有必要时才申请新增依赖。
- `media/`、`assets/local/` 和用户壁纸不得写入日志或上传。
- 所有新增公开函数和方法提供类型注解。
- 第二阶段 A 和 B 分别具备独立测试、独立开关和独立回退路径。

## 方案比较

### 第二阶段 A：窗口适配

#### 方案 A1：将启动动画注入 Codex 页面

动画可以天然继承页面尺寸，但必须把启动器耦合到 Codex 内部页面结构，无法保持独立恢复和失败回退边界。**不采用。**

#### 方案 A2：等待 Codex 主窗口稳定后按整窗外框显示一次

启动器继续独立运行；Codex 主窗口稳定出现后，读取其整窗可见外框和所在显示器，先调整启动器几何，再显示海报、创建媒体画面并开始播放。动画、等待层和 DWM 交接共用该矩形。**采用。**

该方法不再追求点击后的立即可见，而是用一次有限的启动等待换取无小窗跳变、无边框外露和无重复起播。

#### 方案 A3：使用固定的默认窗口或主显示器全屏

实现最简单，但在多显示器、不同 DPI 和用户自定义窗口尺寸下仍然突兀，也无法真正验证 Windows 几何适配能力。**不采用。**

### 第二阶段 B：内部壁纸

#### 方案 B1：外部透明窗口覆盖 Codex

可以实现边框和装饰层，但无法把壁纸放到 Codex 不透明内容的下方。覆盖层还会影响点击命中、拖动、截图和可访问性。**不采用。**

#### 方案 B2：修改 Codex 安装目录

可以深度修改界面，但应用更新会覆盖，恢复困难，并扩大安全和许可风险。**不采用。**

#### 方案 B3：通过本地调试协议注入固定样式

在 Codex 页面内加入固定样式表，使原生根容器和内容表面透明，把壁纸设置为页面底层背景；必要的菜单、输入框和弹窗保持不透明。无需修改安装目录，并可在页面内撤销。**采用。**

#### 方案 B4：仅设置 Windows 桌面壁纸

稳定但只能显示在 Codex 窗口外部，无法形成应用内视觉延续。**不采用。**

## 第二阶段 A：启动器窗口适配

### 启动原则

冷启动时启动器窗口保持隐藏，Codex 在后台启动。目标 Codex 窗口连续稳定后重新读取当前主窗口，在透明状态下完成整窗定位，再恢复不透明并开始媒体播放。壁纸注入与动画并行；页面内容、日志挂载标记和壁纸加载状态都不会暂停或延长动画，动画连续完成后交给当前 Codex 窗口。

激活接口返回进程号后，窗口探测只接受该进程的顶层窗口。同一安装包中仍在退出的旧窗口、启动壳或辅助窗口不得触发首次显示；几何读取失败时启动器继续保持隐藏，并由后续稳定探测重试，不得改用历史最大化矩形。

目标 Codex 窗口稳定出现后，只进行一次几何校准：

1. 读取目标窗口的整窗可见外框和屏幕坐标。
2. 将启动器移动到对应显示器，并调整为整窗外框大小。
3. 在窗口保持隐藏时创建原生句柄并完成矩形锁定，然后只显示一次；可见后不再重新定位。
4. 海报、视频和等待提示铺满整窗可视区域；DWM 过渡和最终交接使用同一目标矩形。

校准完成后不再跟随 Codex 窗口移动或缩放。若目标窗口在等待期间反复变化，则继续探测；若达到 `MaxWaitSeconds` 仍未取得稳定窗口，显示失败状态并退出启动器。窗口枚举因短暂出现多个候选而返回空时，已登记目标仍可接受新的渲染器就绪标记；自动兜底从首个有效 Codex 窗口出现时计算，不从最近一次句柄替换重新计时。

### 几何来源

- 优先使用 `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 获取 Windows 实际可见的整窗外框。
- DWM 外框读取失败时回退到 `GetWindowRect`。
- 窗口选择继续使用第一阶段的进程名、包路径、窗口类、可见性、工具窗口样式和响应性条件。
- 目标矩形必须与所在显示器有有效交集；完全离屏的矩形视为无效。
- 保存几何时只记录坐标和尺寸，不记录窗口标题、截图或用户内容。

### 窗口就绪、首帧与播放

- 启动器窗口在 Codex 主窗口稳定前保持隐藏，不创建可见的小尺寸过渡窗口。
- 首次显示前完成原生矩形设置，随后附加视频输出并只发起一次媒体播放请求。
- 海报和视频采用覆盖式缩放，填满 Codex 整窗外框；非 16:9 窗口允许裁切画面边缘，不保留可见黑边。
- 窗口显示、媒体打开和 Codex 激活继续异步执行；不得因媒体加载阻塞窗口探测。

### 失败与回退

- 找不到稳定 Codex 主窗口：在配置的 `MaxWaitSeconds` 后显示失败状态并退出，不无限隐藏。
- 几何读取失败：不显示错误尺寸的动画；由会话超时流程回到错误提示。
- 保存几何仅在失败提示或特殊回退中使用，不参与正常冷启动的首次可见画面。
- DWM 缩略图失败时继续使用启动器窗口淡出。
- 用户跳过动画：沿用现有交接流程。

### 测试与验收

- 多显示器正坐标、负坐标和不同 DPI 下，启动器与目标整窗可见外框一致。
- 最大化、普通窗口和最小客户区尺寸均能取得有效整窗外框。
- Codex 主窗口稳定前启动器保持隐藏，稳定后才显示并开始媒体。
- 没有稳定窗口时在 `MaxWaitSeconds` 后执行安全回退。
- 校准不会重新创建媒体播放器或重置播放位置。
- DWM 更新和最终交接使用校准后的目标矩形。
- 媒体播放、停留、超时和 DWM 回退测试继续通过。

## 第二阶段 B：Codex 内部壁纸

### 模块定位

内部壁纸是可选增强模块，只在用户明确开启时启用。关闭时不创建额外启动参数、不开放调试端口、不启动注入流程，Codex 按第一阶段路径正常启动。

第二阶段 B 不接管启动动画。启动动画结束后，壁纸模块才在已挂载的 Codex 主页面中安装样式。

首版范围只包括：

- 壁纸本身；
- 让壁纸从原生内容后方显示所必需的根容器、侧栏和主内容表面透明度；
- 为保持文字、输入框、代码块、菜单和弹窗可读性所必需的局部背景调整。

首版不包括按钮、字体、图标、间距、布局、动画和交互控件的重新设计。完整界面皮肤必须依据实际使用反馈和建议另立阶段、设计与验收。

### 启动与连接

1. 读取壁纸开关和经过校验的本地壁纸路径。
2. 从当前用户的应用包注册信息自动选择最新 Store 版 Codex，并刷新本地运行时记录；该记录只用于诊断和启动前提示，不作为最终兼容判定。
3. 选择仅绑定 `127.0.0.1` 的随机高位端口，不允许固定暴露到局域网。
4. 使用与 Codex 应用激活方式兼容的 Python 启动后端传入调试参数。
5. 轮询本地 JSON 调试端点，只接受本次启动且进程归属正确的 Codex 页面。
6. 拒绝非 `127.0.0.1`、端口不一致、包含用户名密码或非目标页面地址的 WebSocket 地址。
7. 页面结构符合当前版本兼容配置且运行时能力探测通过后，再连接并注入固定样式。

页面在应用窗口出现后仍可能继续初始化。能力探测必须在独立等待窗口内持续重试，覆盖主路由挂载完成；超过等待窗口才判定不兼容并恢复原生外观。激活进程路径暂时不可读时也应继续轮询，不能立即按未知版本放弃。

端口、进程号和页面目标只用于校验；日志不得记录认证请求头、页面内容或用户壁纸数据。

### 注入内容

注入内容只包括：

- 一个可识别并删除的样式节点；
- 一组明确列出的主题背景变量；
- 壁纸资源地址；
- 记录原始根元素属性和变量的最小状态；
- 固定的检测、启用、关闭和状态查询函数。

样式必须做到：

- 壁纸位于 Codex 页面底层背景。
- 主聊天区域、侧栏和页面根容器按设计使用透明或半透明表面。
- 菜单、对话框、输入框、代码块和浮层保持清晰可读。
- 不设置全局 `pointer-events: none`，不使用覆盖整个页面的不可见元素。
- 不拦截键盘、鼠标、剪贴板或拖放事件。
- 不使用持续动画、滤镜循环或高频背景重绘。

### 可检测

检测分为注入前和注入后。

注入前至少检查：

- 目标页面和路由符合已登记配置；
- 必要的页面根节点存在；
- 必要的主题变量存在；
- 当前 Codex 版本或页面能力命中已登记兼容配置；
- 调试端点属于刚启动的 Codex 进程。

注入后至少检查：

- 样式节点和皮肤标记存在；
- 壁纸背景地址已经应用；
- 核心背景节点命中预期透明规则；
- 注入过程中没有返回脚本异常。

检测失败时不进行第二次盲目注入。模块记录原因码并恢复原生外观。

### 可关闭

关闭入口包括：

- 配置开关关闭；
- 启动参数显式禁用；
- 运行中固定的恢复快捷键；
- 注入失败后的自动关闭；
- Codex 退出或页面重新加载时清理失效状态。

关闭皮肤后不要求重启启动器。若页面已经无法响应恢复指令，则提示完全退出并重新打开 Codex；重启后因为安装目录未被修改，官方外观自然恢复。

### 可恢复

恢复流程必须：

1. 移除注入的样式节点。
2. 撤销壁纸图片地址并释放 Blob URL 或等价临时资源。
3. 恢复注入前的根元素属性。
4. 恢复注入前被修改的 CSS 变量和优先级。
5. 删除页面内的状态对象。
6. 再次检查关键标记已经不存在。

恢复代码不得使用整体清空页面样式的做法，也不得触碰与壁纸无关的页面状态。

### 版本与兼容

兼容性由激活后进程身份、能力探测和版本记录共同判断：

- 版本号优先精确命中配置；没有精确项时，只允许命中显式登记的主版本系列，例如 `26.*`。
- 能力探测用于确认当前页面确实具备所需节点和主题变量。
- 版本号命中但能力探测失败时，仍拒绝注入。
- 启动前的本地版本记录可能过期，不得在没有激活进程信息时据此关闭调试端口；实际激活后仍必须验证同一包身份。
- 未登记的精确版本和主版本系列默认停用壁纸，不静默尝试未知样式。
- Codex 更新后必须先运行壁纸回归检查，再登记新的兼容配置。

### 隐私与安全

- 调试地址只允许回环地址。
- 只执行项目内置的固定脚本，不接受外部传入的任意脚本。
- 不读取页面文字、聊天、账号、Token、Cookie 或本地存储。
- 不截图，不导出窗口内容。
- 壁纸只从经过校验的本地文件加载。
- 不监听其他应用、不常驻后台、不建立远程连接。
- 调试端口随本次 Codex 进程结束而失效；若端点无法确认由目标进程持有，则终止注入。

### 测试与验收

- 开关关闭时没有调试参数、注入进程或壁纸改动。
- 启动前缓存版本过期时仍可进入实际进程校验；精确版本优先于系列配置，未登记主版本仍被拒绝。
- 错误端口、非回环地址、错误进程和错误页面目标均被拒绝。
- 页面结构不匹配时直接回退原生外观。
- 成功注入后壁纸位于页面底层，菜单、弹窗和输入区域保持可用。
- 壁纸不改变鼠标命中、键盘输入、粘贴、滚动和拖放行为。
- 执行恢复后样式节点、壁纸变量和根元素标记全部消失。
- 在可恢复状态下重新注入不会叠加重复样式。
- 无法恢复时，完全重启 Codex 能让官方外观恢复。
- 日志只包含版本、阶段、布尔结果、耗时和错误码，不包含页面内容或壁纸数据。
- 不使用真实的用户聊天内容进行自动测试。

## 第一阶段的兼容边界

- 第二阶段 A 可以替换启动器的目标几何来源，但不得改变海报首绘、媒体请求和 Codex 启动请求的并行关系。
- 第二阶段 B 不得成为第一阶段启动成功的前提。
